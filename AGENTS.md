# slen-node

## Purpose
`@slen/sdk` — the TypeScript/Node SDK: `new Slen(options)` runs flows and reads their outcome, keeps end customers and their credits, checks webhooks, and writes a journal and spans (with an OTLP export). The same surface as the PHP SDK, call for call (`contract/calls.json`).

This repository is the package itself. `contract/` and the JSON of `examples/help/` are copies of the contract both SDKs share; the contract is kept, and both SDKs are held against the API's OpenAPI spec, in the SDK's source repository.

## Commands
```bash
# No Node on the host: the toolchain runs in a container, from the root of this repository.
docker run --rm -v "$PWD":/app -w /app node:22-alpine sh -c 'npm ci && npm run typecheck && npm test && npm run build'
docker run --rm -v "$PWD":/app -w /app node:20.3.0-alpine node scripts/floor.mjs   # after a build
docker run --rm -v "$PWD":/app -w /app node:22-alpine node scripts/export-help-slice.mjs --check
docker run --rm -v "$PWD":/app -w /app node:22-alpine node scripts/consumer.mjs 7      # and 5.0; needs the registry
# against the API's spec: add -v <dir of the spec>:/spec:ro -e SLEN_OPENAPI_SPEC=/spec/v1.yaml
```
`npm ci` and an install from a tag of this repository (`npm install github:Alexey-Shpilka/slen-node#v0.3.0`) run `prepare`, which builds `dist/`.

## Releasing
A release is an annotated tag `vX.Y.Z` on `master`; `.github/workflows/release.yml` publishes it to npm by trusted publishing (OIDC), with provenance. No npm token exists, here or in the repository's secrets.
1. On a branch: `npm version X.Y.Z --no-git-tag-version` (`package.json` and `package-lock.json`), `SDK_VERSION` in `src/version.ts`, `node scripts/export-help-slice.mjs --write` (the slice carries the version), and in `CHANGELOG.md` what `## [Unreleased]` gathered becomes `## [X.Y.Z] - YYYY-MM-DD` under a new, empty `## [Unreleased]`, the links at the bottom following. Every PR writes its line under `[Unreleased]` as it lands.
2. A pull request, green, merged to `master`.
3. On that commit of `master`: `git tag -a vX.Y.Z -m "slen-node X.Y.Z"`, then `git push origin vX.Y.Z`.
4. `release.yml` runs the gates of `ci.yml` on the tag's commit, refuses a tag whose commit is not on `master` and a tag that is not `v` + the version of `package.json` and of `src/version.ts`, then runs `npm publish`. A failed run publishes nothing: a passing cause (npm down) is a re-run; a fault in the tree is a new version. A pushed tag is never moved or deleted.

**Once, by the owner of `@slen/sdk` on npmjs.com** (the package's Settings → Trusted Publisher → GitHub Actions): organization or user `Alexey-Shpilka`, repository `slen-node`, workflow filename `release.yml`, no environment, and direct `npm publish` allowed — a publisher added now allows only `npm stage publish` unless that is ticked. A new publisher expires unless its first publish succeeds within 2 days: add it just before the first tag goes out. After that release: Settings → Publishing access → "Require two-factor authentication and disallow tokens".

## For AI Agents
- **The gate is `npm run typecheck` and `npm test`**, then `npm run build` and `node scripts/floor.mjs` on Node 20.3.0: some guarantees (the span type, `@ts-expect-error`) are the compiler's, so a green test run alone proves less than it looks.
- **The chain is built in `Slen`'s constructor**, visible in one line: `ApiClient` (checks before the wire, envelope, error mapping, the outcome in the journal) → `RetryClient` (attempts, pauses, `slen.request`/`slen.retry`) → `FetchClient` (one attempt: URL, headers, JSON, the attempt clock).
- **A module sends `ApiRequest`s with a route template and `params`**, never a built path: the journal writes the template, so no value of a path (an external user id may be an email) reaches a log. Templates are the spec's own (`/v1/executions/{id}/status`).
- **Every operation is a value of `ENDPOINTS`** (`http/endpoints.ts`): `METHOD /path` exactly as `operation` in `contract/calls.json`; a request spreads `endpoint(ENDPOINTS.x)` for its `method` and `route`. No other literal of `src/` spells a path or an operation of ours (`test/contract.test.ts`).
- **Modules get a `ModuleContext`** (`api`, `config`, `spans`) and hold it in a private field, so `Object.keys(slen)` is the module names; `SlenConfig` lives in a private field of `Slen` — no printing or serializing of the client shows the key.
- **Building the client touches no network.** A missing key or `fetch` is a `TypeError`; `timeoutMs` not above 0, `retries` not a whole number ≥ 0, `webhookToleranceSeconds` not a whole number ≥ 1 a `RangeError` — programming errors, not `SlenError`s. `Infinity` switches the attempt clock off.
- **The environment is `SLEN_API_KEY` and nothing else.** `SLEN_BASE_URL` is not read: a live key never follows a variable nobody sees in the code. `src/config.ts` is the one file that reads the environment, and `SLEN_API_KEY` the one name (`test/config.test.ts` scans `src/`).
- **The address** is the constant `DEFAULT_BASE_URL` (`https://api.slen.ai`, `servers[0]` of the spec); `baseUrl` is for tests and a local stack only; `/api` is the SDK's to add. No README or example names it (`test/readme.test.ts`, `test/help-examples.test.ts`).
- **Keep every default in `resolveConfig()`** as a `??` chain that starts at the option: the help slice reads the defaults off those chains (`default_known`). A collaborator is stated by its code (`NOOP_LOGGER`, `globalThis.fetch`), a setting by its value.
- **The attempt clock is the SDK's own, never `AbortSignal.timeout()`**: that signal cannot be stopped, and would cut a body that outlives it with a raw `DOMException`. A body that stalls after its headers is a `TimeoutError`; a wire that failed a `ConnectionError`; neither carries a code (`test/timeout.test.ts`, on a real socket).
- **Retry** (`http/retry.ts`): no answer, 429 and any 503, under the same idempotency key on every attempt; every call is safe to repeat. `Retry-After` up to 30 s is waited out, past that the error goes back at once; without it 200 ms × 2ⁿ ±25 %, at most 5 s after the jitter — PHP's `RetryPolicy` is the same. 500, 502, 504 are never repeated: a provider may have been paid.
- **The caller's abort is never repeated** and rejects with the signal's own reason, during a pause too. `retries` of a call's options (`ApiRequest.retries`) overrides the client's for that call; a wait's read is sent once (`0`). An answer after an attempt with no answer carries `afterNoAnswer`.
- **The envelope**: a 2xx is `{ data }`; `envelope: 'page'` wants a `data` list and `meta.next_cursor`; `envelope: false` for `/health`; a 204 answers `undefined`. Anything else is `InvalidResponseError` (`invalid_response`), not repeated, the body never quoted (it may be a flow's output).
- **Refused before the wire** with `InvalidRequestError` (`invalid_request`), nothing sent and nothing written: a blank idempotency key (never swapped for a generated one), a missing or blank route value, a `timeoutMs` of the call not above 0, its `retries` not a whole number ≥ 0. `refuseBeforeTheWire()` runs before a span opens.
- **`transportOf()` is the one place** a call's options become `signal`, `timeoutMs` and `retries` of its request: a module that copies them by hand drops the next one.
- **`fetch` is called detached** (`const send = config.fetch; send(…)`): a browser's `fetch` throws "Illegal invocation" on another `this`. `User-Agent: slen-sdk-node/<version> node/<version>` only where `process.versions.node` exists; a `User-Agent` in `headers` replaces it, the SDK's other headers cannot be replaced. `SDK_VERSION` is held to `package.json` by a test.
- **The journal** (`http/logging.ts`, `LOG_EVENTS`): `slen.request` (debug), `slen.response` (debug, `duration_ms` of the whole call, `request_id`), `slen.retry` (warn), `slen.refused` (info, a 4xx), `slen.unauthorized` (error), `slen.failed` (error, with `error_type`), the two of a wait, `slen.webhook.rejected`.
- **An event has one level**: `writeLog(logger, event, context)` takes it from the table in `logger.ts`.
- **`error_type` is the contract's name of the type** (`Provider`, `Timeout`, `InvalidResponse`), not the class name: one word for both SDKs. Fields are snake_case, as PHP's.
- **Never written**: the API key, `Authorization`, the webhook secret, the idempotency key, bodies, the server's `error.message`, values of the path or the query (`test/core/logging.test.ts` plants values and searches every record). A logger that throws is swallowed; it is called as a method, so a class keeps its `this`.
- **Errors**: `errors.ts` is the hierarchy with the four local codes; `http/error-mapper.ts` holds `BY_CODE` (= `contract/error-codes.json`) and the fallback; `test/errors.test.ts` has no table of its own and checks both ways. `SlenError` carries `code`, `status`, `details`, `requestId`, `retryAfterSeconds` (the `Retry-After` of a refused 429/503).
- **Idempotency**: `generateIdempotencyKey()` is a UUID v4 (from `getRandomValues` where `randomUUID` is missing); `idempotencyKeyForJob(jobId, operation)` is `job:{id}:{operation}`, one key for every attempt of a job; a blank part is a `TypeError`. A runtime without Web Crypto fails with a message that names Node 20.3, not a `TypeError` about `undefined`.
- **No fallback to `node:crypto`** (`webCrypto()`): a static import breaks workers and browsers, and a key or a span id from anything weaker than a CSPRNG is not one.
- **`operations.execute()` / `executeAsync()`**: `customer` is `context.user_id`, `creditType` `context.credit_type`; the same key in `context` with another value (a number read as its string) is refused before the wire, so is a blank `customer` or `creditType`. A key is generated when none is given. The span is named by the call — `operations.execute_async` for a replayed key too.
- **`executions.wait()`**: the server's `retry_after_seconds`, else 1 s doubling to 30 s, ±25 %, at least 250 ms, cut to the deadline; default 300 s, `NaN` → default, at least 1 s, `Infinity` → no ceiling and ten failed reads in a row end it. A read is sent once (`retries: 0`) under what is left of the wait (at least 5 s, at most `timeoutMs`).
- **Its failures and its end**: no answer, 429 and 5xx are waited through (`onPollError`, `slen.wait.poll_failed`), anything else rejects; at the timeout it answers the last state read, or rejects with the failure when none was. `signal` ends it during a read or a pause. One span, `executions.wait`.
- **Type names follow the wire**: `ExecutionResult` (execute), `ExecutionStatusView` (`get`, `wait`), `ExecutionTrace`; `ExecutionStatus` is the union. Answers keep snake_case. A read takes `RequestOptions` (`signal`, `timeoutMs`, `retries`); a call that sends a body adds `idempotencyKey` (`CallOptions`); the options of a call extend them, so one object carries both.
- **The options are named as PHP names its classes** (`ExecuteOptions`, `WaitOptions`, `CustomerListOptions`, `AccountOptions`, `BlockOptions`, `MovementOptions`, `EntryListOptions`, `PriceListOptions`, `VerifyOptions`, `WebhooksOptions`): one name in Help & Docs for both SDKs; no earlier name is kept (`test/exports.test.ts`).
- **The status of a run is read with `isPending`, `isFinished`, `isCompleted`, `isRejected`** (`executions/wait.ts`, exported): PHP has them as methods of its DTOs, so an example never lists statuses by hand.
- **`withLogger(logger)`** answers a new `Slen` built from the resolved config with that logger and the client's own recorder as `spanRecorder`: the same `fetch` (its connection pool), one OTLP buffer, one `flush()`; the first client never changes.
- **A request's context goes on a copy**, never on the shared client: `test/core/slen.test.ts` makes 100 calls at once through two copies, and `test/core/worker.test.ts` 1 000 through a copy each, and finds every record in the logger of its own request (the answer echoes the idempotency key as `X-Request-Id`).
- **`customers`** writes no span. `list()` always sends `view=customers` and `limit` (50); `search` is `q`; `create()`, `unblock()` and `block()` without a reason send `{}`; `updateAccount()` puts the whole settings. The wire is PHP's, so one `expect.json` holds both.
- **`view=customers`**: backend `v1.0.15` answers the old page of accounts without it; from the next backend release the page of customers is the only one, `view` takes the single value `customers` and any other is `422`.
- **A movement** always sends `credit_type` (`default`); refused before the wire: `credits` that is not a decimal string of at most four places (`/^-?\d+(\.\d{1,4})?$/`), zero, negative on `topUp`/`charge`, an empty `creditType`.
- **`delete()` after no answer**: the request names `doneAfterNoAnswer: 'customer_not_found'`, and `ApiClient` reads that 404 as the 204 it stands for — only when an earlier attempt got no answer.
- **Webhooks need no client**: `webhooks` is a `WebhooksModule` with no secret and no logger, `slen.webhooks` one with `webhookSecret`, `webhookToleranceSeconds` and the client's logger. The secret is the call's, else the module's; none, or a blank one passed, is a `TypeError` before anything is checked.
- **`verify` and `constructEvent` take three parameters**: the secret is `secret` of `VerifyOptions`, beside `toleranceSeconds` and `now`; a fourth argument does not compile (`test/modules/webhooks.test.ts`).
- **The check** (`signature.ts`): no or a blank header → `missing_header`; exactly one `t` of digits and at least one `v1`, else `malformed_header`; `|now − t|` over the tolerance → `outside_tolerance`; none matches → `no_matching_signature`.
- **A `v1` counts only as 64 lower-case hex characters** and is compared with `crypto.subtle.verify('HMAC', …)` over the raw bytes `{t}.{body}`: constant time, no string comparison anywhere.
- **`constructEvent()`** throws `WebhookSignatureError` (`webhook_signature_invalid`, `reason`) for a refused signature and `InvalidResponseError` (`webhook_payload_invalid`) for a signed body that is not an event. Every refusal writes one `slen.webhook.rejected` (warn: `reason`, `age_seconds`), never the body, the header or the secret.
- **Events are a union narrowed by `type`**: the four typed ones have a literal `type`; `UnknownWebhookEvent.type` is the closed list of the other 22 names — a `string` member would keep it in every narrowing. An event added later still arrives as unknown at run time. `contract/webhook-vectors.json` holds the check; `test/modules/spec.test.ts` holds the names to `webhooks:` of the spec.
- **A span carries money, ids and a verdict — never a prompt.** Ten fields (`observability/span.ts`), held to `contract/span-attributes.json`; `SPAN_FIELDS` and `SlenSpan` are checked against each other by `tsc`, and the `@ts-expect-error` of `test/span-carries-no-prompt.test.ts` stops a widened type. Do not add a "debug payload" field.
- **`SpanScope` is closed once**: `execution(run)` reads the verdict off the run (`rejected` → `refused`, `failed`/`uncertain` → `error`, else `ok`; `cacheHit` null while the run has no answer), `failed(error)` is `refused` for `SpendRefusedError` and `PolicyDeniedError`, `error` otherwise. It reads the run structurally, so `observability/` imports no module.
- **A recorder never fails a call**; `MultiSpanRecorder` keeps going past one that throws. `OtlpSpanRecorder.flush()` chains its batch onto the one in flight, so a flush waits for everything, and a lost batch goes to `onError`; a span it cannot give an id to (no Web Crypto) is dropped and told, not thrown.
- **The contract test** (`test/contract.test.ts`) has a row per line of `contract/calls.json` (18); `NOT_CALLS` = `webhooks.verify`, `webhooks.constructEvent`, `flush`; the values of `ENDPOINTS` are the operations of the table, both ways (`FOREIGN_PATHS`: `/v1/traces` is the collector's).
- **A method of `Slen` that answers a `Slen`** (`withLogger`) builds another client and is no call — neither a row nor in `NOT_CALLS`, as `SlenSdk::withLogger()` in PHP; the exporter and `help-slice.test.ts` classify it the same.
- **`TYPE_FILES` are read with the compiler** and compared with the spec's schemas field by field: a type is in `SHAPES` or in `NOT_COMPARED`, and every difference allowed is in `KNOWN_DIVERGENCES` — each with its reason, held both ways.
- **Help examples** (`test/help-examples.test.ts`): every `examples/help/*/node.ts` is imported on `FakeFetch` with the harness's key in `SLEN_API_KEY` and a moved clock; the checks that only read files are made for the `node.ts` files and for the JSON of every example (the PHP SDK checks its own files; the two languages together are checked where the contract is kept), and `RETIRED` keeps the names the SDK no longer has out of every region. Rules: "Help examples" below.
- **At most three parameters** for every function, method and constructor of `src/`; more go in one object (`RetryPolicy`, `RetryPause`, `SpanSubject`, `SignatureRule`). `test/source-hygiene.test.ts` holds it with the compiler.
- **No `else`** in `src/` or a `node.ts` (`test/source-hygiene.test.ts`, with the compiler) nor in a block of the README: a function of the region whose branches `return` (as in `execute`, `wait`, `errors`), or `if`s that do not lean on each other; a status is read with `isCompleted`, `isRejected`, `isPending`.
- **The help slice** (`test/help-slice.test.ts`): `help-slice.json` is rebuilt with `scripts/export-help-slice.mjs` and compared; after a change of the surface run `node scripts/export-help-slice.mjs --write` and commit the file. `NAMED_NOT_EXPORTED` is `Clock` and `ModuleContext`.
- **The README is held to the code** (`test/readme.test.ts`): every `slen.…(` call it shows is a method of the client, nothing the SDK took out is named, the `run.status` line lists `ExecutionStatus` whole, an input of `execute` carries `messages`; every function this file or the README names is spelled in the package. The README rows about money are `test/errors.test.ts`'s.
- **Comments in `src/`**: six lines at most, no history, no plan numbers; the reasons live here (`test/source-hygiene.test.ts`).
- **Nothing internal in any file of the package** (`test/source-hygiene.test.ts`, the patterns this tree was checked with before its first commit): no path of a machine, plan or its numbers, private repository, local stack, earlier name of the product or real-looking key; a test address is `https://api.test`. A guard spells its own patterns with character classes.
- **A doc comment of the public surface** — an export of `src/index.ts` or a public member of one — is one line of prose, then tags, on that line where they fit (`/** Summary. @throws SlenError */`): it is what a caller's editor shows, the one documentation read without leaving the code.
- **Everything else is tags only**: `/** @internal */` on what a module exports and the package does not, no doc on what is not exported. A `//` says only what must be seen at that line (an order, a deliberate negation, an empty `catch`).
- **Comment lines are at most a tenth of `src/`** (a line starting `//`, `/*` or `*`): a reason added to the code instead of here shows up there first.
- **Every network call rejects with a `SlenError`** for a refusal, no answer, or an answer that cannot be read: its doc says `@throws SlenError` and no more; the README says which type means what.
- **What ships** (`files`): `dist/`, `README.md`, `LICENSE`, `CHANGELOG.md` and `package.json` — `npm pack --dry-run` shows exactly these. `version` is the release, and `src/version.ts` says the same (`test/core/http.test.ts`); `publishConfig` is public with provenance.
- **The floor is Node 20.3, held by running what ships**: `scripts/floor.mjs` loads `dist/` (ESM and CJS) on 20.3.0 and takes it through a retry, the journal, a run and its wait with spans out through OTLP, a page of customers, a 204, the attempt clock and every webhook vector. The toolchain runs on Node 22.
- **Two compilers, one `tsc` link**: `typescript` (7) builds and typechecks; `typescript-api` (6 under another name) is imported by the four tests that read the AST and by the slice exporter, because 7 exports no compiler API. Both ship a `tsc`, and `node_modules/.bin/tsc` is whichever npm linked last, so every script that compiles names 7 by its path — `prepare` too, through `build`, and with it `npm publish` in the release (`test/toolchain.test.ts`). Dependabot leaves the majors of both, and of `vitest`, to an iteration.
- **The types are held where a consumer reads them**: `scripts/consumer.mjs` compiles the help examples against the packed `dist/*.d.ts` on TypeScript 5.0 (the oldest 5 that reads them) and on 7, with Node's resolution and a bundler's (`typescript-consumer` in CI). A declaration that only our compiler accepts fails there, not in a user's build.
- **No `@types/node`**: a test that needs `node:fs` or `node:http` describes the members it uses structurally and imports through a specifier the compiler does not resolve.

## Help examples
`examples/help/<id>/` is code the console's Help & Docs prints: an article shows a region of `node.ts`, never code of its own. `example.json` (`languages`, `regions`, `responses` — the answers in order) and `expect.json` (`calls` — every request, compared whole; `prints` — every line written) are the same files in both SDKs.
- **`node.ts` is imported as it is**, with `globalThis.fetch` replaced by a `FakeFetch` fed from `responses`, the harness's key in `SLEN_API_KEY` and a moved clock. A run is given up on when its own clock passes ten minutes or twenty seconds of real time pass.
- **Regions**: the lines between `// docs:start <name>` and `// docs:end`, each marker on a line of its own, name `[a-z][a-z0-9-]*`, no nesting, a name once per file, never empty; exactly the regions `example.json` lists, in that order. What a reader does not see (`declare const process`, `export const recorded`) stays outside with a `// Harness:` comment, and a region reads only names a region of the same file brings in or the runtime gives.
- **What an example shows**: the SDK as the code has it and without an address (`NAMED_NOWHERE`: no `baseUrl`, `SLEN_BASE_URL`, "base URL", not even to say it is left out); keys as `sl_live_…`; an idempotency key derived from the unit of work; no `else`, the status read with `isCompleted`/`isRejected`/`isPending`; nothing the SDK no longer has (`RETIRED`) or never documented (`NOT_SHOWN`).
- **With the spec** every answer an example is served and every body it is expected to send is held against the schema of its operation — for every example in the tree, a PHP-only one too.
- **A change to a call an example makes is finished when the example is green again**; the JSON changes where the contract is kept, and comes here as a copy.

## The help slice
`help-slice.json`: what the console's Help & Docs may say about this SDK without reading its source. `node scripts/export-help-slice.mjs` prints it, `--write` writes it, `--check` exits 1 naming what differs (2 — a command line it does not know, a slice it could not build, a file it could not write or read); `--out <file>` names another file.
- **The bytes**: UTF-8, LF, two spaces, one line break at the end, non-ASCII and slashes not escaped; no date, no absolute path, no commit; lists sorted by `name` by code unit unless in the order of the source.
- **The top level**: `schema` (`2`: paths from the root of this package), `language` (`node`), `package` (`{ name, version, manifest: "package.json", runtime, dependencies }` — `dependencies` and `peerDependencies`, `optional` from `peerDependenciesMeta`), `client` (`Slen` / `SlenOptions`), `options`, `config_file` (`null`), `calls`, `symbols`.
- **An option** is a member of `SlenOptions`: `{ name, type, required, default, default_known, env, description }`; `default` is `null` or `{ code, value }`, read off the `??` chains of `resolveConfig()`; `default_known: false` where no chain starts at the option; `env` — `SLEN_API_KEY` for `apiKey`.
- **A symbol** is an export of `src/index.ts`, printed as the published declarations: `{ name, kind, source, deprecated, internal, alias_of, modifiers, type_parameters, extends, implements, signature, members }`, `source` as `src/…`.
- **A call** is a public member reachable from the client, named as a caller writes it after the client (`operations.execute`, `health`): `{ name, symbol, member, deprecated, internal, signature, operation }`, `operation` copied from `contract/calls.json`, `null` for `webhooks.verify`, `webhooks.constructEvent` and `flush`; `withLogger` is not a call. A signature may name a type `src/index.ts` does not export — `Clock` and `ModuleContext` (`NAMED_NOT_EXPORTED`).
- **What holds it**: `test/help-slice.test.ts` — committed equals fresh, and the slice against `resolveConfig()`, the text and the run-time exports of `src/index.ts` and a real client.
